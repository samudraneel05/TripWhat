- The HITL question cards (LangGraph `interrupt()`) survive reloads. The month options correctly start from next month.

- Hinglish input ("Mujhe December mein Goa…") is understood: friends → 3 adults, beaches.
- Test suites are green: backend 130, frontend 42. Every dead file listed in the previous audit has been removed.

## 4. P0 — Critical (security, capacity, broken setup)

### P0-1 · Image proxy is an unauthenticated open proxy (SSRF + stored XSS vector)
- **Evidence (live):** `GET /api/image?url=http://127.0.0.1:5000/openapi.json` → 200 with our OpenAPI JSON. `?url=https://example.com/` → 200 `text/html`, served from our origin (and through the Vite/nginx `/api` proxy, the *frontend* origin). `?url=http://169.254.169.254/...` was attempted (timed out locally, but on a cloud host it can reach the metadata service).
- **Where:** `backend-python/app/routes/image_proxy.py:38-114`
- **Root cause:** No auth, no host allowlist, `follow_redirects=True`, origin `content-type` passed through, and arbitrary bodies ≤ 5 MB cached in Postgres (`image_cache` is already the largest table at 17 MB).
- **Fix:**
  1. Allowlist hosts the app actually uses: `lh3–lh6.googleusercontent.com`, `maps.googleapis.com`, `places.googleapis.com`, `images.unsplash.com`, `*.ggpht.com`, SerpApi image hosts. Compare the parsed hostname, not a string prefix.
  2. Resolve DNS and reject private, loopback and link-local IPs. Disable redirects, or re-validate every hop.
  3. Only accept `image/*` content types. Always respond with `Content-Type: image/*`, `X-Content-Type-Options: nosniff`, and `Content-Security-Policy: default-src 'none'`.
  4. Cap the stored size at ~1–2 MB and set a per-IP rate limit.
- **Done when:** a test asserts internal URLs, non-allowlisted hosts and non-image responses return 400/415, and allowlisted Google photo URLs still work.

### P0-2 · Socket.IO has no authentication; events leak across users
- **Evidence (live):** An anonymous `socketio.AsyncClient` emitted `join:conversation <victim-id>` and received `agent:tool_start`, `agent:widget` and `agent:response` for user A's conversation (`/tmp/audit/probe_socket.py`).
- **Where:** `backend-python/app/main.py:22-41` (connect/join have no auth); `frontend/src/stores/tripStore.ts:258-263` (no token sent); `backend-python/app/services/link_import.py:475` (`sio.emit("saved:imported", payload)` with no `room`, so it goes to all clients, payload includes `userId` and place names).
- **Fix:**
  1. Frontend: `io(SOCKET_URL, { auth: { token } })`.
  2. Backend `connect(sid, environ, auth)`: verify the JWT, reject if invalid, store `user_id` with `sio.save_session`, and `enter_room(sid, f"user:{user_id}")`.
  3. `join:conversation`: load the conversation and only `enter_room` if `conversation.user_id == session.user_id`.
  4. `link_import.run_import`: `await sio.emit("saved:imported", payload, room=f"user:{user_id}")`.
  5. On logout, call `socket.disconnect()`. Today `disconnectSocket` is a no-op (`tripStore.ts:433-436`), so the socket survives a user switch.
- **Done when:** integration test: an unauthenticated connect is refused; user B cannot join user A's room; `saved:imported` reaches only the owner.

### P0-3 · No LLM capacity management (429 storm), no per-user limits
- **Evidence:** With 4 simulated users, 181 `RateLimitError` lines (`Limit 30000 TPM … gpt-4o`). Each failed turn shows the user "I'm sorry, I encountered an error processing your request." One single-city build makes ~111 external calls (22 Google Maps, 12 Maps MCP, 38 OpenTripMap, 9 OpenAI, 1 SerpApi, ~29 photo fetches).
- **Where:** `backend-python/app/agents/travel_agent.py:161-162` (gpt-4o for all onboarding, default retries); `backend-python/app/routes/chat.py:84-121` (no per-user concurrency/rate limit).
- **Fix:**
  1. `ChatOpenAI(..., max_retries=6)` plus exponential backoff that honours `retry-after`. On a persistent 429, fall back to `gpt-4o-mini` for that call.
  2. Shrink the onboarding prompt. The system prompt plus 16 tool schemas is ~3.1k tokens: trim examples and drop tool descriptions duplicated in the prompt. Consider `gpt-4o-mini` for plain turns (chitchat, Q&A) and gpt-4o only when planning tools are needed.
  3. Per-user limits: ≤ 1 active run per user, ≤ N messages/min (Redis token bucket). Return a clean 429 that the frontend renders as "You're sending messages too quickly."
  4. Global semaphore on concurrent agent runs, sized to the TPM budget.
  5. Ops: raise the OpenAI usage tier before launch, or route through a provider with more headroom.
- **Done when:** a load test with 5 concurrent users finishes with 0 user-visible errors (slower is fine), and a test simulates a 429 on the first call and asserts recovery.

### P0-4 · Secrets written to logs
- **Evidence:** 879 lines in the backend log containing `key=AIza…`, `apikey=…`, `api_key=…` (httpx/httpx2 INFO request lines with full URLs).
- **Where:** `backend-python/app/utils/logger.py:6-10` (root logger INFO); every service calling keyed GET URLs.
- **Fix:** Set `logging.getLogger(name).setLevel(logging.WARNING)` for `httpx`, `httpx2`, `httpcore`, `httpcore2`, `openai._base_client` and `urllib3`. Also add a logging filter that redacts `(key|apikey|api_key|token)=[^&\s]+`. Rotate the Google Places, SerpApi and OpenTripMap keys, since they have been written to log files on disk.
- **Done when:** a unit test logs a URL with `?key=SECRET` through the configured logger and asserts `SECRET` is absent from the output.

### P0-5 · Raw provider errors (with OpenAI org ID) sent to clients; failed turns not persisted
- **Evidence:** `agent:response.error` and the Redis replay contain `"Error code: 429 … organization org-oAdX9… Limit 30000…"`. After a reload, a failed turn shows the user's message with no reply.
- **Where:** `backend-python/app/routes/chat.py:358-372`
- **Fix:** Log the full exception server-side. Send a stable error code (`rate_limited`, `upstream_unavailable`, `internal`) plus a friendly message. Persist an assistant message for failed turns (flag `error: true`) so history stays consistent, and offer a "Retry" button in the UI that re-sends the last user message.
- **Done when:** a test forces an exception in `chat_stream` and asserts the payload has no provider text and the DB contains an assistant error message.

### P0-6 · Unauthenticated Google Places endpoints (billing abuse)
- **Evidence:** `GET /api/places/search?query=cafe` returned 200 with no token. `/api/places/details` triggers 1 details + up to 5 photo resolves + 1 nearby search = **7 billable Google calls per request, unauthenticated**.
- **Where:** `backend-python/app/routes/places.py:12-35`
- **Fix:** Add `Depends(get_current_user)` to `search`, `autocomplete` and `details`, plus per-user rate limiting. Cache details by `placeId` (a `places_cache` table already exists).
- **Done when:** a 401 test without a token passes and the frontend `PlaceDetailPanel` / `AddItemInline` still work (they use the authed axios client).

### P0-7 · Auth hardening (empty passwords, brute force, account takeover, token in URL)
- **Evidence (live):** register with `password=""` → 200, `"a"` → 200, `name=""` → 200, `name` of 500 chars → **500 Internal Server Error**. `Case_x@Example.com` and `case_x@example.com` → two separate accounts. 30 rapid bad logins → 30×400, never throttled.
- **Where:** `backend-python/app/schemas/auth.py:6-15`; `backend-python/app/routes/auth.py:53-81, 230-256`; `backend-python/app/config.py:46`
- **Fix:**
  1. Schema: `name: constr(strip_whitespace=True, min_length=1, max_length=200)` and `password: constr(min_length=8, max_length=128)`. Reject passwords whose UTF-8 encoding is over 72 bytes, or pre-hash with SHA-256 before bcrypt.
  2. Normalise email to lowercase on register, login and the Google callback. Add a unique index on `lower(email)`; migrate existing duplicates.
  3. Rate limit `/login`, `/register` and `/google/callback` (per IP + per email) with `slowapi` or Redis.
  4. Google callback: require `claims["email_verified"] is True`. **Do not auto-link** to an existing password account unless that account's email is verified. Otherwise require logging in with the password once to link. (An attacker who pre-registers `victim@gmail.com` with a password currently takes over the victim's account when they later use Google sign-in.)
  5. Replace `password=_hash_password(google_email + settings.jwt_secret)` (deterministic) with `_hash_password(secrets.token_urlsafe(32))`, or a nullable password plus `auth_provider` column.
  6. Stop putting the JWT in the redirect query string (`auth.py:252-256`, it leaks to history, logs and Referer). Use a one-time code exchanged via POST, or the URL fragment (`#token=`) read and cleared immediately by `GoogleAuthSuccess.jsx`.
  7. Fail fast at startup when `jwt_secret == "fallback-secret"` or is shorter than 32 bytes and `node_env != "development"`.
  8. Return 401 for invalid credentials.
- **Done when:** tests cover each validation rule, case-insensitive uniqueness, throttling after N attempts, and Google login refusing an unverified email or auto-link.

### P0-8 · Flight booking is not human-confirmed
- **Where:** `backend-python/app/agents/tools/flight_tools.py:56-110`. Confirmation is only a docstring hint ("IMPORTANT: always confirm…").
- **Risk:** With a live Duffel token the model can create a real paid order without explicit confirmation. Passenger PII (DOB, email, phone) also goes into checkpoints and LangSmith traces.
- **Fix:** Inside `book_flight`, call `interrupt({"type":"booking_confirmation", offer, price, passenger})` and only create the order when the resume value is an explicit confirm. Render this as a dedicated confirmation card (not free text). Guard live mode behind an env flag such as `ALLOW_LIVE_BOOKINGS=false`. Redact PII from LangSmith via `hide_inputs`/`hide_outputs`.
- **Done when:** a test asserts `create_order` is not called until a resume with `{"confirm": true}`.

### P0-9 · Fresh install / deploy / CI are broken
- **Evidence & where:**
  - `backend-python/app/agents/tools/search_tools.py:9` imports `langchain_tavily`, which is **not in `pyproject.toml`**, so `pip install -e ".[dev]"` (README + CI) fails at import. (It works locally only because it was installed by hand.)
  - `backend-python/Dockerfile:6` hardcodes a pip list missing `python-dotenv`, `redis`, `langgraph-checkpoint-postgres`, `psycopg[binary]`, `cryptography`, `yt-dlp`, `google-genai` and `langchain-tavily`. The container dies on `from dotenv import load_dotenv`. It also runs a single `uvicorn` process.
  - `docker-compose.yml` has no Redis service, but `stream_buffer` requires `REDIS_URL`.
  - `.github/workflows/test.yml:3-7` triggers on `modernization`/`master`; the default branch is `main`, so **CI never runs**. `node-version-file: '.nvmrc'` points at a missing file.
  - `frontend/package.json` `lint` script fails: ESLint 9 with no `eslint.config.js`.
- **Fix:** Add `langchain-tavily` to `pyproject.toml`. Change the Dockerfile to `COPY . . && pip install --no-cache-dir .`, with a non-root user and a healthcheck. Add `redis:7` to compose and pass `REDIS_URL=redis://redis:6379` to the backend. Set CI triggers to `[main]`, add `frontend/.nvmrc` (e.g. `20`), and run `tsc --noEmit` and lint in CI. Add a flat `eslint.config.js` with `react-hooks` and `@typescript-eslint` rules, covering `ts,tsx,js,jsx`.
- **Done when:** a clean `python -m venv && pip install -e ".[dev]" && pytest` passes, `docker compose up` serves a working chat, and CI goes green on a PR to `main`.

## 5. P1 — Core experience correctness (agent and itinerary quality)

> These came from the real-user simulation (§7). Fix the generic causes, not the individual cases.

### P1-1 · Agent reports edits that did not happen
- **Evidence:** "Swap day 2 and day 3" → two `move` calls, each moving **one activity**, and the reply says the days were swapped. The itinerary was unchanged. "Remove the first activity on day 1 and add teamLab Planets" → the first activity remained, teamLab was appended, and the reply said "removed". In the Lisbon UI run, "make day 2 more relaxed and add a fado show in the evening" → the reply claimed "Relax at Jardim da Estrela" (not in the itinerary). Day 2 grew from 5 to 6 items, and the fado show landed at **11:33**, overlapping another activity.
- **Where:** `backend-python/app/services/itinerary_editor.py:15-75` (add), `:77-116` (remove), `:128-168` (move); `backend-python/app/agents/tools/itinerary_tools.py:195-285`
- **Root causes:**
  1. `remove_activity` / `move_activity` return a success message even when **nothing matched** (`removed is None`). They match only an exact `id` or exact `title`, so "the first activity" or a fuzzy name matches nothing.
  2. There is no `swap_days`, `reorder_day` or "make lighter" action. The model improvises with single-activity moves.
  3. `add_activity` picks the slot by `period == time_slot` and **falls back to `slots[0]`**. Built itineraries use timed slots without `period`, so evening additions go into the first morning slot.
  4. The slot model keeps both `activity` and `activities` per slot, which invites partial updates.
  5. Edits search places near `cities[0]` (`itinerary_tools.py:246`), which is wrong for multi-city trips.
- **Fix:**
  1. Return a structured result `{ok: bool, changed: [...], error?}` from every editor op. When `ok` is false, the ToolMessage must say *"No change made: <reason>. Activities on day N are: [id: name, …]"* so the model can retry with real IDs.
  2. Add actions: `swap_days(a, b)`, `remove_activity(day, index)` (1-based position), `set_time(day, activity_id, start, end)`, and `lighten_day(day, max_items)`.
  3. Place additions by time: evening = after 18:00. Recompute start/end times, never overlap, and append a new slot at the right time if needed.
  4. Normalise to `activities[]` only. Keep `activity` as a derived mirror for the frontend until it's migrated.
  5. Use the day's own city (`day.city` / `day.location`) for place searches.
  6. Return the **final day contents** in the ToolMessage, and add a system-prompt rule: "Only describe changes that appear in the tool result."
- **Done when:** unit tests for each action (including no-match → `ok:false`) pass, and the harness scenario `full_spec_then_edits` shows the swap reflected in `tripState.itinerary.days`.

### P1-2 · Response text narrates a different itinerary than the one built
- **Evidence:** Rome reply listed "Colosseum… Borghese Gallery", neither of which is in the itinerary. The Seoul and Taipei replies described Gwangjang/Hongdae and Shilin/National Palace Museum while the built days were Myeongdong/Lotte World and Chengzhong Market/Simple Kaffa. The Tokyo reply ends "Would you like to see the detailed day-by-day itinerary?" when it's already displayed.
- **Where:** `backend-python/app/agents/tools/itinerary_tools.py:181-185`. The `build_itinerary` ToolMessage only says `"Days: N, Cities: …"`, so the model invents contents.
- **Fix:** Put a compact day-by-day summary in the ToolMessage (top 3 names per day plus hotel). Add a prompt rule: after `build_itinerary`, summarise **only** from the tool result in ≤ 4 sentences, and never list places that aren't in it.
- **Done when:** in the harness, every place name mentioned in the final message appears in `tripState.itinerary` (add as an automated evaluator).

### P1-3 · Route night-split LLM fails on every agent call → even splits, no geographic order
- **Evidence:** `[PLAN_TRIP] Route LLM failed: No JSON object found` ×19, always followed by "Even split of N nights per city". Italy's route came out Rome → Florence → **Venice → Amalfi → Cinque Terre** (zig-zag). The same function **works when called standalone** (`/tmp/audit/repro_route.py`).
- **Where:** `backend-python/app/agents/tools/plan_tools.py:52-57`
- **Root cause (likely):** Inside the streaming graph run, `response.content` arrives as a **list of content blocks**. Line 53 converts it with `str(...)` *before* the list check on line 55, so `parse_json_robust` sees a Python repr and finds a list, not an object.
- **Fix:** Use `response.text` (LangChain ≥ 0.3) or extract the text blocks first. Better: use `with_structured_output(RouteProposal)` with a Pydantic schema. Log `type(response.content)` once to confirm.
- **Done when:** a unit test feeds a list-of-blocks `AIMessage` and gets a dict, and the backend log shows LLM rationales in harness runs.

### P1-4 · Itinerary builder: filler days, missing days, thin days, wrong place types
- **Evidence:**
  - Generic filler activities ("Explore {city}", "Local experience in {city}", "Evening in {city}"), from log `Empty cluster for X day N, using LLM fallback`, appeared in Lisbon ×2 days, Bali, Paris, Vietnam, Cambodia ×2 and Thailand ×2.
  - Lisbon: `Clustered 50 places into 4 clusters: [2, 15, 6, 27]` for a 7-day trip gave Day 1 only 2 items and days 6–7 filler.
  - Italy 14 days → **11 days**; SE Asia 21 days → **19 days**. Route nights (6+6+6) don't match `cities` (8+6+6) or the duration (21).
  - Hotels as activities ("Château des Fleurs Hôtel & Spa", "Hotel Denim Seoul", "Seoul N Hotel", "KyCo Peninsula Resort"); convention centres ("Feira Internacional de Lisboa", "Fira de Barcelona", "Palazzo dei Congressi"); out-of-season events ("Seoul Rose Festival" in October); "Bali" itself as an activity; tour-operator listings ×3 for one Nusa Penida tour.
  - Every activity typed `attraction`, ratings mostly `None`, and OpenTripMap 1–7 ratings mixed with Google 1–5.
  - Tokyo/Kyoto 5 days: Day 5 returns to **Tokyo after Kyoto**, Kyoto gets 1 day and no temples (user asked for temples). Relaxed pace still gets 5–6 items per day.
- **Where:** `backend-python/app/services/itinerary_builder.py` (clustering ~L1000-1060, `_curate_day_activities` L270-315, `_llm_fallback_activities` L838-844); `backend-python/app/services/query_generator.py`
- **Fix:**
  1. Cluster into exactly `num_days` groups (k-means with k = days, or balanced partitioning). If places run short, **search more** (broaden queries, increase radius) before falling back. Never emit placeholder names: if real places still can't be found, return fewer activities and a day note.
  2. Assert `len(days) == duration` and that per-city day counts match `routeProposal`. Reconcile `cities[].nights` with `routeProposal` in one function.
  3. Filter out `lodging`, `convention_center`, `event_venue`, `travel_agency`, `real_estate` and other non-visitable types. Exclude event queries ("festival", "{Month} {Year}") unless the event dates are verified. Dedupe by `placeId` and by similar names.
  4. Map Google `types` to activity types (`restaurant`, `cafe`, `museum`, `park`, `market`, `place_of_worship`). Normalise ratings to a 5 scale and drop OTM ratings.
  5. Respect `pace`: relaxed ≤ 3, moderate ≤ 4, packed ≤ 6 items per day. Respect ordering: all days in a city are contiguous and follow `routeProposal` order.
  6. Countries passed as destinations ("Vietnam, Cambodia, Thailand") must be expanded into cities (ask, or choose the top 2–3 per country) before building. Add transfer days between distant cities.
- **Done when:** builder unit tests assert no placeholder names, `len(days) == duration`, no lodging-type activities, contiguous city days, and per-day caps by pace. Harness scenarios `long_sea_trip`, `italy_region` and `budget_paris` pass these checks.

### P1-5 · Preferences, budget and dates are lost or mis-normalised
- **Evidence:**
  - "food and temples" → `preferences=['food']`; "food and history" → `['food']`; Goa "beaches aur party" → `['beaches']`; Seoul "food and nightlife" → `['food']`.
  - "under $800 total" was parroted in the reply, but `budget=None`. `plan_trip` has **no budget parameter** and hotels ignore it. Luxury hotels (Signiel, Shilla, Rocco Forte) were picked for solo trips with no budget given.
  - Dates: "mid-November" → Nov 6; "around christmas" → Dec 4–10; "late October" → **`dates=None`** (itinerary days had no dates); "weekend in January" → Jan 1–3 (New Year's Day); "August 14–16 2026" (already past) planned without any warning.
  - Hotels ignore traveller type: "Honeymoon Hideaway" villa for a family with 2 kids, "Deluxe Family Suite" for a couple, "Queen Room with **Shared Bathroom**" as the top solo pick, a 5★ listing with **1 review** ranked best. Multi-city trips only get hotels for the first city.
- **Where:** `backend-python/app/agents/tools/plan_tools.py:91-290`; `backend-python/app/agents/state.py:59-180`; hotel ranking in `itinerary_builder.py` / `serpapi_provider.py`
- **Fix:**
  1. `plan_trip`: accept `interests: list[str]` (keep every interest) and `budget: {amount, currency, scope: "total"|"per_night"|"per_day"}`. Store them in `trip_state` and feed them to query generation and hotel filtering (SerpApi supports `max_price`).
  2. `normalize_dates`: accept a `qualifier` (`early|mid|late`), holidays ("christmas" → Dec 20–27, "new year", "diwali" and similar), and "next week"/"this weekend". Prefer letting the LLM pass ISO dates: tell it to resolve qualifiers itself, and keep the parser as a fallback. Never return `None` for a recognisable month.
  3. Reject or flag past dates. The tool returns "dates are in the past — confirm or choose new dates" and the model asks via `ask_question`.
  4. Hotel ranking: Bayesian rating (`(R*v + C*m)/(v+m)` with m ≈ 50 reviews). Penalise "shared bathroom". Match the room to the party size and type. Pick one hotel **per city**.
- **Done when:** unit tests for the date phrases above, and harness checks that `preferences` includes every stated interest, `budget` is set and respected, and there's one hotel per city.

### P1-6 · Forced `tool_choice="required"` turns greetings and off-topic messages into question cards
- **Evidence:** "hi there" → question card "What can I help you with today?" (5 options + "Let TripWhat decide"). "Write me a python function…" → the deflection was rendered as a question card. "thanks!" was then consumed as the **answer** to the pending card.
- **Where:** `backend-python/app/agents/travel_agent.py:55-84` (regex `_CHITCHAT_RE` misses "hi there", "hello!!", "good morning" and similar), `:208-224`
- **Fix:** Replace the regex gate with a cheap intent classifier (gpt-4o-mini, JSON `{intent}`), or widen the regex and only force tools when `_PLANNING_HINT_RE` matches. Never let `ask_question` carry plain deflections: options `None` + `allow_custom` → respond in text. When a pending interrupt exists and the new message is clearly not an answer (chitchat, or a brand-new request), cancel the interrupt and start a fresh turn instead of resuming with it.
- **Done when:** harness `greeting` and `off_topic` scenarios produce text-only replies with no `question_card` widget.

### P1-7 · `ask_question` recorded as a failed tool with a raw `Interrupt(...)` repr
- **Evidence:** In stream events and persisted `toolActivities`, `ask_question` has `status:"error"` and `error:"(Interrupt(value={...}))"`. The UI happens to hide it, but replay and analytics treat it as a failure.
- **Where:** `backend-python/app/agents/travel_agent.py:99-108` (`_is_interrupt_error` checks `Interrupt` but the error object is a `GraphInterrupt` exception or a tuple wrapper), and `:531-538`
- **Fix:** Also treat `GraphInterrupt` (`langgraph.errors.GraphInterrupt`) and any exception whose `.args[0]` contains `Interrupt` objects as interrupts.
- **Done when:** a unit test with a `GraphInterrupt` error yields `summary="Waiting for your answer"` and `error=None`.

### P1-8 · Auto-build path overwrites the agent's reply and concatenates messages
- **Evidence:** Replies like "…I'll get started on this plan for you!Your trip to Bali is all set…" (two messages glued together, no space). Some replies are replaced by the canned "I've put together your itinerary! Check it out on the right…".
- **Where:** `backend-python/app/agents/travel_agent.py:658-700`; token accumulation at `:584-611`
- **Fix:** Separate the text of each model step (`"\n\n"` between AI messages). When the auto-build fallback runs, append a short note instead of replacing `response_text`. Also log when the fallback fires, since it means the model skipped `build_itinerary`.

### P1-9 · Frontend auth error messages never reach the user
- **Evidence:** Wrong password shows "Login failed" (backend returns `detail: "Invalid credentials"`). The "This email is already registered — sign in instead?" branch in `SignupPage.jsx:65,101` **never triggers**, because signup throws `"Signup failed"`.
- **Where:** `frontend/src/contexts/AuthContext.jsx:80,112` (reads `error.message`; FastAPI sends `detail`)
- **Fix:** `throw new Error(error.detail || error.message || "…")`. Also handle 422 arrays (`detail[0].msg`).
- **Done when:** a vitest test mocks a 400 `{detail:"User already exists"}` and asserts the "already registered" UI shows.

### P1-10 · System prompt date is frozen at import time and examples are stale
- **Where:** `backend-python/app/agents/prompts.py:6-17, 254` (`DEEP_AGENT_SYSTEM_PROMPT = _build_system_prompt()` runs once per process); examples hardcode "Aug 2026", "Sep 2026" and "Oct 2026", which are already past.
- **Fix:** Build the date header per call (inject it via `dynamic_model_selection` as part of the system message override), and make the examples relative ("<next month>"). `datetime.today()` in `state.py:94,148` should also use the user's timezone if known (DTZ lints).

## 8. P3 — Polish, performance, maintainability

- **Bundle:** 2.77 MB / 805 KB gz in one chunk. Use `React.lazy` for routes, split `mapbox-gl`, `gsap`, `d3-geo` and `world-atlas`, and load the landing globe lazily.
- **Unused deps:** remove the 10 packages listed in §3 (2.3).
- **Types:** fix the 2 `tsc` errors; migrate `AuthContext.jsx`, `LandingPage.jsx`, `LoginPage.jsx`, `SignupPage.jsx`, `ProfilePage.jsx` and `App.jsx` to TS; replace the `any`s in the stores.
- **Single HTTP client:** move `tripStore` raw `fetch` calls to the axios `api` instance (`lib/api.ts`).
- **Console noise / PII:** `AuthContext.jsx` logs user objects (`console.log("[AUTH] User data received:", data)`). Remove all 8 `console.log`s in `src/`. Enable React Router v7 future flags to silence warnings.
- **Ruff:** 285 findings (84 blind `except Exception`, 73 B008, 41 import order, 36 UP017). Run `ruff --fix` for the 98 auto-fixable ones; narrow the blind excepts in network code.
- **Error boundaries:** add a route-level `ErrorBoundary` with a "Something went wrong — reload" fallback.
- **SEO/meta:** add a meta description, Open Graph/Twitter tags and a real favicon (currently `/vite.svg`).
- **Accessibility:** the send button has no `aria-label`; the icon buttons rely on `title`. Add labels and visible focus styles.
- **Stop generation:** there's no way to cancel a 60 s build. Add a Stop button that cancels the run (cancel the task, keep the checkpoint consistent).
- **Chat header title** stays "New trip" after planning; use the trip title.
- **`.env.example`:** list every key (§3, 7.8). Add `VITE_MAPBOX_TOKEN` to `frontend/.env.example` and remove the unused `VITE_GOOGLE_MAPS_API_KEY` / `VITE_OPENWEATHER_API_KEY`.
- **Account lifecycle:** add password reset, email verification, account deletion and data export (GDPR), and revoke Google tokens on deletion.
- **Image cache in Postgres:** blobs bloat the DB. Move to object storage or a CDN, or cap the total size with LRU.
- **Observability:** Sentry (frontend and backend), request IDs in logs, a cost/latency dashboard per turn (LangSmith already traces; add token cost per user).
- **Language:** reply in the user's language when the input isn't English (Hinglish case).

- macOS, Python 3.12.11, Node via Vite 5.4.21, Postgres + Redis local, Chrome for Playwright.
- External services reachable: OpenAI, Google Places / Maps MCP, OpenTripMap, SerpApi, Tavily, Duffel (test). The proxy in `.env` is commented out.

### Commands used
```bash
# static
cd backend-python && source .venv/bin/activate && python -m pytest -q && ruff check app --statistics
cd frontend && npx vitest run && npx tsc --noEmit -p tsconfig.json && npm run build && npm run lint
# live
uvicorn app.main:asgi_app --port 5000            # backend
npm run dev -- --port 5173 --strictPort          # frontend
python /tmp/audit/probe_api.py                   # API/security probes
python /tmp/audit/probe_socket.py                # socket eavesdropping
cd /tmp/audit && python agent_harness.py         # 17 real-user scenarios
NODE_PATH=frontend/node_modules node /tmp/audit/ui_audit.cjs   # browser walkthrough
```
